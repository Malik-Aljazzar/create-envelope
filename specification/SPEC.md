## Resolved this pass

- **Two fatal crashes caused by Envelope 0.7.5's own JEI mixins breaking against newer JEI (19.52.0.421+)**, surfaced in production on 2026-10-01 right after updating JEI to 19.57.0.450: (1) `Critical injection failure: Callback method onTransferRecipe(...) in envelope-common.mixins.json:jei.BasicRecipeTransferHandlerMixin from mod envelope failed injection check, (0/1) succeeded. Scanned 0 target(s). No refMap loaded` - crashed world load outright, and on this setup left the client's `javaw` process hung (`Responding: False`) instead of showing a clean crash screen; (2) a second crash in the same mixins file, `jei.JeiKeyConflictContextMixin`, that hit as soon as JEI handled its first keypress/click in a world - usually froze the game rather than showing a crash screen either. Root cause: Envelope's own JEI-recipe-transfer and JEI-key-conflict mixins target JEI-internal classes/methods whose shape moved in newer JEI releases; Envelope ships no refmap for either mixin, so a target mismatch is a hard crash instead of a soft-fail.
  - Immediate workaround: pinned `jei` back to `19.57.0.449` (last known-good pairing with Envelope 0.7.5) on both the client instance and the server's `mods_update` staging folder.
  - Real fix shipped in `create_envelope` 1.0.2 (this mod): cancels Envelope's own two broken mixins via MixinSquared's `MixinCanceller` API and replaces them with this mod's own `JeiRecipeTransferMixin` (keeps "moving a mail recipe from JEI into the packing table fills in the recipe's address" working against old and new JEI alike) plus an equivalent replacement for the key-conflict mixin, so JEI keys (show recipe, toggle overlay, ...) still get correctly ignored while typing in an Envelope screen. MixinSquared is bundled in this mod's jar - nothing extra for a server/pack to install. Should JEI's internals move again, only the address-autofill shortcut stops working; the game no longer crashes either way.
  - Once 1.0.2 was live on both client and server, `jei` was moved back up to `19.57.0.450` on both sides. Verified: clean server boot afterward (console `Done` in ~7s, no `InjectionError`/`Mixin apply for mod` failures in the log).
